Why it feels different

Built for operators who need calm control, not one more fragile layer.

Local first

Scripture, songs, text overlays, and mapped local media should stay usable on the machine running OBS.

Explicit output

Selection is private. Take updates the mapped output. Hide text affects text only.

OBS-native mindset

Emberstage works with scenes, sources, and operator habits already inside OBS instead of building a second desktop switcher.

Core interaction

The service rhythm stays simple.

  1. 01

    Find

    Search Scripture, songs, text drafts, cameras, or mapped media.

  2. 02

    Select

    Build the next cue privately without assuming viewers can see it.

  3. 03

    Review

    See what is next, where it is mapped, and whether OBS reports it on program.

  4. 04

    Take

    Apply the selected cue to its mapped output target with an explicit action.

  5. 05

    Hide text

    Clear the text overlay immediately without touching media or stream state.

Dock family

Separate docks for the work people actually do during service.

Text

Scripture

Media

Cameras

Switch included camera sources inside the mapped output scene without switching the OBS program scene.

Setup

FAQ

Clear boundaries matter.

Does Emberstage replace OBS?

No. The product direction here is for docks and mapped control inside OBS, not a second video compositor.

Can the local core still matter without cloud features?

Yes. This page is intentionally built around the local operator workflow first.

What does Take mean?

Take explicitly applies the selected cue or source action to its mapped target. Selection alone is not treated as live output.

What does Hide text affect?

Text only. It should not imply camera, media, or stream shutdown.

Is managed streaming available from this site?

Only on a configured Emberstage server. Local Core remains usable without an account, billing, or provider OAuth.
